# 多来源数据连接框架

这是一个 Go 开发基础，用统一批次输出读取多个本地虚构来源，不访问真实账号。

## 约定

- `Connector` 负责创建和恢复来源专属快照；`Cursor.Token` 对运行器不透明。
- 游标中的偏移只在同一个 `SnapshotID` 内有意义，不把会随增删漂移的普通页码当成可靠边界。
- `Record.DataID` 由来源、类型、外部 ID 与版本派生，崩溃后允许重放时可用该身份识别重复记录。
- 运行顺序是“批次原子落盘 → 检查点原子推进”。输出成功但检查点未推进时，恢复会再次写出同一个确定性批次；`FileSink` 按 `BatchID` 幂等处理。
- 新增来源只需实现 `Connector` 和 `Snapshot`，不需要修改检查点结构。

## 首轮来源

- `EntityMapSource`：按稳定 ID 排序的实体表，模拟翻页期间新增、删除和版本变更。
- `AppendLogSource`：追加日志，模拟翻页期间继续追加数据。

两种来源都会在 `OpenSnapshot` 时固化记录集合；翻页期间来源变化不会进入当前快照。若检查点引用的快照不可恢复，连接器返回显式错误，而不是退回不可证明完整性的页码扫描。

## 跨进程恢复

- `SnapshotStore` 把快照记录集持久化到磁盘，来源对象在进程退出后全部重建时，仍可用检查点里的旧游标接续当时那份扫描，而不是切到最新数据冒充继续。
- `AppendLogSource.UseDataFile` 把追加日志落盘，重建后的来源对象能读回退出前已追加的记录。
- 快照在内存和磁盘上都失效时，恢复返回 `SnapshotExpiredError`，明确给出可恢复范围：失效偏移之前已输出的记录有效，剩余记录无法靠续扫恢复，必须重新扫描该来源。运行器向上传播该错误，不静默跳过剩余记录。

## 验证

运行 `go test ./...`。测试覆盖快照中翻页期间的增删改，以及第二批输出后、检查点推进前注入崩溃并恢复。
